# Downstream review follow-up — 2026-10-13

This follow-up addresses the source/CI review of the AiApi integration. Results
below describe local component and source checks. They do not establish RC
readiness or replace an authenticated client run and platform CI builds.

## Reference review before implementation

The preserved Nagram, Nagram XF and Extraless sources were revisited before
changing the features. Their `SecretChatHelper` implementations use stored DH
parameters for rekeying; there is no equivalent asynchronous DH-config failure
path to reuse. FreshGram therefore releases only the reserved incoming exchange
belonging to the failing request and preserves later exchanges.

Nagram has stock server transcription only. XF is the interface reference for
provider selection; its transcription HTTP client is separate from Telegram
networking and its worker pool is unbounded. Extraless provides the useful local
inference principle: one worker, lazy model use. FreshGram applies bounded,
cancellable scheduling and explicit HTTP egress rather than copying the mobile
implementations. Client `Auto` is provider selection, not failure fallback.

References are preserved under `transcription-review/{nagram,nagramxf,extraless}`
outside this checkout; the earlier comparison is
`transcription-review/TRANSCRIPTION_PROVIDERS_REVIEW.md`.

## Executable local checks

From the checkout root:

```sh
python3 tools/sync_aiapi.py --check
python3 tools/sync_aiapi.py --check --source /path/to/AiApi-rs
python3 -m unittest discover -s tools/tests
c++ -std=c++20 -Wall -Wextra -Werror -I Telegram/SourceFiles \
  Telegram/SourceFiles/test/crypto/secret_rekey_test.cpp \
  -o /tmp/opencode/secret-rekey-review-test
/tmp/opencode/secret-rekey-review-test
```

Native component tests require C++20, pkg-config, Qt6 Core/Network, FFmpeg
development libraries and the `ffmpeg` CLI. The source-extraction fixtures
replace session/network/DH plumbing, not the tested state-machine methods.
Audio tests compile the actual decoder against real FFmpeg with an audio-only
factory adapter; application logging and hardware setup are omitted. Link
wrappers inject terminal failures after successful frames. Tests use disposable
profiles and loopback servers.

The Qt loader harness lives in `Telegram/SourceFiles/test/recognition` and can
be configured independently of Telegram Desktop:

```sh
cmake -S Telegram/SourceFiles/test/recognition -B /tmp/opencode/recognition-checks \
  -D VOICE_ASR_TEST_LIBRARY="$PWD/Telegram/ThirdParty/voice-asr/target/debug/deps/libvoice_asr.so"
cmake --build /tmp/opencode/recognition-checks --parallel 2
ctest --test-dir /tmp/opencode/recognition-checks --output-on-failure
```

From `Telegram/ThirdParty/voice-asr`:

```sh
cargo fmt --all --check
cargo test --all-targets --no-default-features --locked
cargo clippy --all-targets --features local --locked -- -D warnings
python3 tests/abi_smoke.py target/debug/deps/libvoice_asr.so
```

The core workspace also passes its 52 tests. The adapter passes 44 tests and
the C ABI smoke, including proxy forwarding and blocked network operations.
The Qt loader passes real success/error/cancellation calls, rejects legacy
cloud modules and keeps compatible legacy local modules usable; reloading the
same path still checks the required network capability.
Native/source tests include PFS retry, layer compatibility,
secret routing, proxy propagation, scheduler limits, real decoding and crash
cleanup; the standalone PFS decision binary passes 24 assertions. Changed C++
translation units pass syntax checks using the configured compilation database
and regenerated language headers. YAML, Python, source digests and whitespace
are checked independently.

The Python suite passes 17 tests, including the existing rebranding checks.

The adapter workflow now runs snapshot checks on Linux, Windows and macOS and
the native regressions on Linux. Snapshot verification remains a prerequisite
of module installation/building.

## Remaining validation and distribution constraints

Publish the matching dependency image using `Build environment`, then run the
Linux client build. The updated Windows checkout check and module packaging
also need their native CI run. The earlier macOS OpenAL connection reset is a
dependency-download failure; native macOS compilation/deployment still needs
its own successful run.

Authenticated PFS exchange/restart and voice/round-video/secret-media routing
need test accounts/messages. Live Groq/Gemini and cleanup need real credentials.
The queue tests establish dispatch/request limits; long-recording RSS/VRAM and
real GPU cancellation require runtime measurements. Decoder tests cover
reported failures and corruption flags, not every container repair behavior
that FFmpeg might silently accept.

Temporary files are plaintext during a job. Startup cleanup removes marked
orphans after a crash, not files while a crashed application remains stopped.
Legacy unmarked system-temporary directories are not adopted into the new
managed lifecycle.

Automatic module delivery is still a future feature. Before implementing it,
artifacts need an authenticated signed manifest and verification before
`QLibrary::load()`, binding hashes to ABI, platform, architecture, instruction
requirements and accelerator flavor. ABI and unsigned checksums do not establish
module provenance. Manual module selection retains the trusted-plugin model.

The standalone core is published at `https://github.com/Olyaham/AiApi-rs`.
`SOURCE.json` records its clean Git revision alongside the snapshot content
identity; dirty or non-Git sources do not claim a committed revision.
